# UAT test matrix: IT Help Desk (JSM Free)

**Scope:** 20 simulated tickets submitted through the customer portal (plus one raised by an agent on a customer's behalf, T17). They cover routing, priorities, approvals, waiting states, customer replies, resolution, reopening, knowledge base access, Slack notifications, and SLA behavior, including negative cases.

**Run dates:** Day 1 (T01–T10), Day 2 (T11–T20). Both runs happen on weekdays between **09:00 and 17:00 America/New_York**, so the business-hours SLA timers actually run. The tickets are split across two days to stay under the Free plan's 100 emails/day.

**Configuration under test:** the real SLA goals (High 1h/8h, Medium 4h/16h, Low 8h/24h, NY Business Hours), 5 automation flows, and `it-agents-available` = Lead, Alex, Sam.

## Defect log
| Defect ID | Found in | Description | Severity | Fix | Retest result |
|---|---|---|---|---|---|
| F-21 | T02 | The *Report a software problem* form still used the template's **Urgency** field instead of **Priority**, so "High" from the customer never set Priority: no Slack alert and the wrong SLA goal. Phase 2 had fixed only the hardware form | High | Removed Urgency/Impact and added Priority (same label and help text as the hardware form); checked the other forms | Pass (ITHD-19) |

| F-22 | T03 | Design observation: any customer comment on a *Resolved* ticket (even "Thanks!") reopens it and starts a new resolution SLA cycle, which inflates reopen counts | Low | Accepted for the lab. Possible improvements: auto-close Resolved tickets after N days, or reopen only on an explicit customer action | n/a |
| F-23 | T08 | The *Cancel request* transition sets resolution **Won't Do** instead of **Canceled**, so reports can't tell "customer withdrew" from "IT refused" | Medium | Set the *Cancel request* transition's resolution to Canceled in both workflows | Pass (ITHD-26) |
| F-24 | T13 | Observation: because new requests are private by default (F-07), the **Organization** field isn't set on new tickets, so department-level reports can't group new tickets | Low | Accepted and documented; could be fixed with an automation that copies the reporter's organization | n/a |
| F-25 | T14 | Unavailable-agent fallback fails intermittently: a JQL condition evaluated at event time reads Jira's search index, which doesn't yet reflect a brand-new ticket or assignment (it passed once in R5c by timing luck) | High | Moved the check to a **scheduled** rule (hourly JQL sweep), so it runs after indexing. Trade-off: reassignment happens within an hour, with the triage queue as the backstop | Pass (ITHD-32, ITHD-33) |
